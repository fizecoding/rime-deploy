# 输入法体系部署全记录

> 2026-11-07 ~ 11-08 凌晨，一次性完成的完整部署
> 环境：macOS 27.0.1 / Apple Silicon / 微信 4.1.11 / 鼠须管 Squirrel 1.1.2
> 配置文档：《~/Library/Rime/配置说明.md》《~/Library/Rime/恢复指南.md》（随 iCloud 备份）
> 本文是过程记录——为什么这么做、踩了什么坑、怎么解的。

---

## 一、目标

1. 输入法完全本地化，去除搜狗的数据上传
2. 用个人语料（微信聊天记录）训练词库
3. 符合个人打字习惯：中文一律空格上屏，其余符号打断并原样输出
4. 全量备份与可恢复

## 二、阶段记录

### 阶段 1：现状分析与搜狗清除

- 发现搜狗在未使用状态下后台运行（CPU 累计 40+ 分钟），HTTPStorages/cookies 等联网痕迹齐全
- 清除：进程 → root 权限删应用与自启动项（`/Library/LaunchAgents/com.sogou.*`）→ 用户数据 20 余项
- 同时关闭 Rime 的 iCloud 词库同步（当时"全本地"要求；后期按需重建了备份体系）

### 阶段 2：本地方案选型

| 候选 | 结论 |
|---|---|
| **白霜拼音 rime-frost** ✅ | 185 万词、语料重统词频、全套双拼方案、完全离码 |
| 雾凇拼音 rime-ice | 同源，词频较旧 |
| fcitx5-macos | 前端整体更换，动静大 |

### 阶段 3：微信语料导出（最难的一段）

**失败路径**：wx-dump-mac（内存扫描 `x'...'` 十六进制密钥串）→ 4.1.10+ 微信不再在内存存明文密钥，扫描为 0

**成功路径**：[TANGandXUE/wcdb-key-tool](https://github.com/TANGandXUE/wcdb-key-tool)
1. 微信副本重签名（`~/Applications` 下 ad-hoc 副本，不动原版）——注意 root 也无法直接改 /Applications（App Management TCC 保护）
2. 数据库以**用户身份快照**到普通目录（root 经脚本运行会被 TCC 挡住读不了 `~/Library/Containers`）
3. LLDB 断点 `CCKeyDerivationPBKDF`（系统 CommonCrypto 公开符号）+ 微信内退出重登触发 passphrase 计算
4. PBKDF2-HMAC-SHA512（256k 轮）逐库派生密钥，HMAC 校验 22/22 全过，全量解密
5. `real_sender_id = 本人wxid` + `local_type=1` 过滤 → **112,446 条纯文本、126 万字**

**语料训练**：jieba（装载白霜全词表对齐分词）→ 词频统计 → 已收录词提权 11,923 / 新词收录 284（人名/项目/术语）+ 英文词 914（RTK/IMU/GNSS…）

### 阶段 4：系统接入（坑最密集的一段）

| 症状 | 根因 | 解法 |
|---|---|---|
| 鼠须管装了从来用不了（用户当初因此转投搜狗）| 4 月部署时编译缓存写进 App 包（`SharedSupport/build/` 26 个文件），**官方签名被破坏**，TIS 拒绝注册 | 移出后加的文件，`codesign -vv` 恢复 valid |
| `TISSelectInputSource` 一直 paramErr（macism 同败）| 本机输入源选择 API 损坏（疑似搜狗被击杀时占着会话），**重启也不恢复** | 偏好写入 `AppleSelectedInputSources` + 重启 `TextInputMenuAgent`（`caps-switch-cn.sh`）；此后一切切换走 Rime 内部，不走系统 API |

### 阶段 5：按键体系

- 部署初期做过 Caps 键中英切换 + 键盘灯指示（含一个 IOKit 直写 Caps 灯的工具 `set_caps_led.c`，macOS 27 起用户态写灯被系统拒绝，仅作诊断工具保留）；该体系依赖的改键工具后来卸载，**现行按键行为如下**：
- 方案切换全部走 Rime 内部：`F4` / `Ctrl+`` 方案菜单；各方案另绑 F18 直达互切（中文方案 ⇄ easy_en）
- Shift 点按 = 鼠须管内部中英；Shift 按住 = 大写；`Cmd+任意键` **永远到不了输入法**（macOS 规定）→ 清码用 `Esc`/`Ctrl+Backspace`

**符号打断**（个人习惯：中文全靠空格，其余符号原样输出）：
- 坑 1：旧配置 `,.-=[]` 翻页键在候选菜单存在时吃掉符号 → 移除翻页绑定（翻页改 `-`/`=` 与方向键/Page）
- 坑 2：Rime 句号上屏机制把 `abc.` 变成 `ABC。` → recognizer 正则 `ascii_raw: '^[A-Za-z0-9]+[.,;:?!@#%^&*()_+|~<>].*$'` 让符号保持在缓冲区，空格原样上屏
- 尝试过 Lua 处理器（按符号立即上屏，免空格）——**这版 Squirrel 的 librime-lua 不加载 lua/ 模块**（白霜自带的 rq 日期/农历/以词定字其实也一直静默失效），任何 lua_processor 引用会破坏整个按键链 → 放弃，纯 YAML 实现

### 阶段 6：备份体系

- `~/Library/Scripts/rime-backup.sh` + LaunchAgent：每天 22:00 + 开机时增量备份到 **iCloud 云盘/RimeBackup**
- 覆盖：词库全部、userdb、全部配置、脚本、启动项、两份文档
- 只增不删（本地误删不传染）；文档记录了五个灾备场景的恢复命令

## 四、常用命令速查

```bash
# 重新部署鼠须管（改配置后）
"/Library/Input Methods/Squirrel.app/Contents/MacOS/rime_deployer" --build \
  ~/Library/Rime "/Library/Input Methods/Squirrel.app/Contents/SharedSupport" ~/Library/Rime/build
killall Squirrel; sleep 1; open "/Library/Input Methods/Squirrel.app"

# 手动备份 / 重新训练语料
bash ~/Library/Scripts/rime-backup.sh
python3 ~/wxexport/train_personal_dict.py <语料> ~/Library/Rime ~/Library/Rime/personal.dict.yaml

# 更新白霜（注意 rime_frost.dict.yaml 被覆盖需重加 "- personal"）
cd ~/Library/Rime && git pull && 重新部署
```
